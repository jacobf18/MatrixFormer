MatrixFormer

A pretrained transformer that fills in the missing entries of any numerical matrix: ratings, panels, sensor grids, tables. No training, no fine-tuning, no hyperparameters to tune.

Zero-shot

Pretrained once on synthetic matrices. At inference, one forward pass completes your matrix. No weights are updated.

Any shape

Attention along rows and columns works for any number of rows and columns. Large matrices are processed in overlapping windows.

Observed entries kept

Only missing cells are predicted. Every observed value is returned exactly, in its original units.

Inference speed

TabImpute builds a separate prediction problem for every missing entry. MatrixFormer completes the whole matrix in one forward pass. With 10 columns, the speedup grows from 2.1× at 16 rows to 107× at 1,024 rows: 4.17 s for TabImpute vs 0.039 s for MatrixFormer-Impute.

How it works

Each matrix cell becomes a token. Eight transformer blocks alternate attention along rows and along columns, so every cell can borrow information from its row and its column. A decoder then predicts a distribution over the missing value.

Scroll sideways to see the full diagram →

One expert network, about 78M parameters. MatrixFormer+ runs two of these experts and blends them (below).

Normalize each column

Observed values are standardized per column, so columns in very different units become comparable. Predictions are mapped back afterwards.

Embed every cell

Observed values pass through a small MLP. Missing cells get a learned mask token. A missingness embedding tells the model which is which, and learned CLS tokens border each row and column.

Alternate row and column attention

Each block first lets cells in the same row attend to each other, then cells in the same column, then applies a per-cell feed-forward layer. Stacking eight blocks spreads information across the whole matrix.

Decode a distribution

For each cell the decoder outputs probabilities over 5000 value bins. The prediction is the mean of that distribution, which is written into the missing cells only.

Trained only on synthetic data. Both experts learned from randomly generated matrices with varied structure and missingness patterns. No real ratings or tables were used for gradient updates.

Where the 78M parameters live

Each expert has exactly 77,998,496 parameters. The eight transformer blocks hold 85% of them. The decoder is large too, because its last layer maps 1536 features to 5000 bin logits. The cell encoder is tiny: it only has to lift one scalar into a 768-dimensional token.

The token grid

An R × C input becomes an (R + 12) × (C + 12) grid of 768-dimensional tokens. There are no position embeddings at this stage; position enters later through RoPE inside attention.

  • Observed cell: its standardized value goes through Linear(1, 768) → GELU → Linear(768, 768).
  • Missing cell: replaced by one shared, learned mask token.
  • Every cell then adds a missingness embedding, one of two learned vectors, so the model always knows which cells are real.
  • 12 row-CLS tokens are prepended to every row, and 12 column-CLS tokens to every column. They are identical across rows (or columns) at input and become per-row and per-column summaries as attention runs.
  • Corner tokens are the sum of a row-CLS and a column-CLS embedding.

CLS tokens act as learned scratch registers. The decoder never reads them: it decodes only the R × C data cells.

Axial attention: global context in one block

Full attention over every cell would compare all RC tokens with each other. MatrixFormer instead factorizes attention along the two axes. Each block runs two separate attention layers with their own weights: first every row attends across its columns, then every column attends across its rows. After those two steps, a cell has seen its row, and through each cell in its column, every other row too. A single block already has a receptive field covering the whole matrix. Eight blocks repeat this mixing.

Cost per block, 2000 × 1000 window
Full attention over all tokens4.1 × 10¹² pairs
Axial (rows, then columns)6.2 × 10⁹ pairs
Reduction≈ 670×

Token pairs scored by attention, including the 12 CLS rows and columns. Axial cost grows as RC(R + C) instead of (RC)².

  • 16 heads of width 48, bidirectional, no masking or dropout (PyTorch scaled_dot_product_attention).
  • Rotary position embeddings on half of each head (the first 24 of 48 dimensions), base 10,000. The position is the row or column index within the window.
  • CLS tokens are not rotated. RoPE starts after the 12 CLS positions, so they stay position-free registers.

Block anatomy

# pre-norm residual updates; α are learned scalar gains
h ← h + αrow · RowAttn( RMSNorm₁(h) )
h ← h + αcol · ColAttn( RMSNorm₂(h) )

# SwiGLU feed-forward, applied to every token independently
n = RMSNorm₃(h)
h ← h + αffn · Wout( SiLU(Wgate n) ⊙ Wval n )
  • Pre-norm with RMSNorm (ε = 10⁻⁶) before each of the three sublayers.
  • Learned residual gains. Each sublayer's output is multiplied by its own learned scalar α before it is added back, in the style of ReZero.
  • SwiGLU feed-forward with hidden width 1536: a gated unit with separate gate and value projections.
  • Separate weights for row attention and column attention in every block: 16 attention layers in total.

Decoder: a distribution, not a point

For each data cell, a three-layer GELU MLP outputs 5000 logits. A softmax turns them into probabilities over 5000 value bins defined by fixed borders (assets/borders.pt), in units of column standard deviations. The imputed value is the mean of that distribution:

x̂ = Σk softmax(logits)k · mk
  • Bins are not uniform. About 300 bins cover each unit near the center, roughly 0.003 standard deviations wide. Half of all bins fall within ±4.2 standard deviations.
  • The range is wide: borders run from −93 to +87 standard deviations, so outliers stay representable.
  • The two edge bins are open-ended tails. Their representative values come from a half-normal fit rather than the bin midpoint.
  • The softmax and mean are always computed in float32, even under BF16 autocast.

Bin borders per one-standard-deviation interval, from −16 to +16. 37 borders lie outside this range.

Scaling to large matrices

Global column normalization

Means and population standard deviations come from the observed entries of the whole matrix before any windowing. An entirely missing column gets mean 0 and scale 1.

Overlapping windows

Each axis is cut into windows of at most 2000 rows and 1000 columns. The last window is shifted back to end at the edge, so it overlaps its neighbor. Cells covered twice get the average of both predictions. For example, 4500 rows split into [0, 2000), [2000, 4000) and [2500, 4500).

Exact streaming

Within a window, attention runs in batches of 32 rows or columns, the feed-forward in chunks of 8192 tokens, with in-place residual updates. Every sequence is still attended in full, so streaming bounds memory without changing the math.

The hidden grid stays in float32 even under BF16 autocast: about 6.3 GB for a full 2000 × 1000 window, on top of the weights. Use smaller max_rows and max_cols to reduce it, at the cost of less context per window.

Training

Like prior-data fitted networks (TabPFN) and TabImpute, MatrixFormer never sees a real dataset during training. It learns from an endless stream of synthetic complete matrices, each masked into a reconstruction task. Details below follow Section 2 and Appendix A of the paper.

Three phases, one architecture

Each phase continues from the best checkpoint of the previous one. Two frozen teacher models, trained beforehand from the base checkpoint, guide the main and size-extension phases.

The synthetic data prior

The main phase draws from four equally likely matrix families. Together they vary rank, the shape of the singular-value spectrum, the geometry of the singular vectors, matrix size, and which entries are observed.

FamilyRank kTail exponent α
Low-rank2–160.2–2
Slow tail2–1600–0.5
Steep tail2–1601–2.5
Latent factor1–11n/a

The three spectral families build T = U diag(s) Vᵀ with orthonormal U, V. Each singular value blends a fast-decaying head with a power-law tail and a terminal taper:

wj = (1 − e−ω) e−tj/H
gj = [ wj e−(tj/h)p + (1 − wj) τ (1 + tj)−α ] · e−λ (tj/(k−1))q
sj = smax · gj / g1,   tj = j − 1

The input adds tiny Gaussian noise (σ ≤ 10⁻³), but the target keeps the full clean signal. The latent-factor family sets T = PQᵀ, with each factor vector drawn from a Gaussian, Laplace, Student-t, spike-and-slab or centered Dirichlet distribution. It is kept at base-phase sizes as rehearsal, because training on spectral matrices alone degraded performance on it.

Singular-vector geometry

Each axis independently picks one of four constructions before QR orthonormalization: Gaussian (a uniformly random basis), coherent (variation concentrated in a few rows), smooth (random cosine features) or offset-bearing (a near-constant first direction).

From matrices to training episodes

Each family is paired with one of two masking schemes, giving eight equally weighted components: fixed 40% MCAR, or a mixed kernel that samples a missingness mechanism per matrix. Missingness can therefore depend on the values themselves.

Mixed mechanismProbability
MCAR: missing completely at random0.30
MAR: depends on observed values0.20
MNAR: depends on the hidden values0.20
Censoring below or above a quantile0.10
Two-phase subsampling0.10
Skip logic0.05
Cluster-level missingness0.05
  • Missing rate: 40% with probability 0.25, otherwise 0.05 + 0.7·B with B ~ Beta(2, 2), so it ranges from 5% to 75%.
  • Sparse-support thinning in 75% of episodes mimics new users with few ratings. The matrix is transposed with probability ½, then 10–40% of rows are picked and keep observations in only a log-uniform 1–60% of columns. The loss is scored on those rows' hidden entries.
  • Normalization applies one per-column affine map to both the masked input and the clean target. For sparsely observed columns the variance is shrunk toward the pooled within-column variance: (SSc + v̄) / (nc + 1).

Teacher–student objective

The model is trained to predict a full distribution for every hidden entry. Its probabilistic terms are supervised by the true value. Its point prediction is instead distilled toward two frozen teachers: models with the same architecture that receive the same masked input. Their averaged predictive mean, with gradients stopped, becomes the point target.

# per scored hidden entry, averaged over the set S
L = −log pθ(y)
  + 2 · ρ( μθ − sg[ ½(μψ₁ + μψ₂) ] )
  + 0.05 · (1/O) Σk ( Fθ(b̃k) − 1{y ≤ b̃k} )²

# ρ = Huber loss with threshold 1
  • Negative log-likelihood of the true value under the bar distribution trains the full predictive density.
  • CDF alignment is a ranked probability score at the 5000 bin midpoints, a discrete form of CRPS.
  • Huber, not squared error, for the point term: with squared error, a few extreme residuals dominated the point loss.
  • Teachers are training-only. Inference is a single forward pass of one model.

The recommender specialist: MatrixFormer-RecSys

MatrixFormer-RecSys shares the architecture and differs only in its weights. It is fine-tuned on synthetic rating matrices that look like recommender data: very sparse, with heterogeneous users and popular items. The settings below come from the released checkpoint's config; the paper describes this expert only briefly.

  • Synthetic only: no real ratings in any gradient update, and model selection used inner synthetic validation only.
  • Rating episodes of 1000 × 1000 with only 0.4%–8% of entries observed, drawn from mixed user-preference families.
  • Realistic noise: per-user noise levels and power-law item popularity.
  • Recommender normalization: two-way (user and item) centering with per-user scaling.
  • Objective: point loss on expected rating RMSE, plus small weights on NLL (0.1), MAE (0.1) and a ranking term (0.05).
  • Short fine-tune: 400 updates at learning rate 5 × 10⁻⁶ from an earlier recommender checkpoint.
  • User-balanced query sampling, and the released weights are an exponential moving average (decay 0.95).

MatrixFormer+: a two-expert blend

MatrixFormer+ runs two experts with the same architecture: a general imputation model and a recommender-system specialist trained on sparse, rating-like matrices. It then picks one mixing weight for your matrix from how well each expert reconstructs the entries you did observe.

# per-cell errors on observed entries, column-standardized
eg = (general − x) / σ
es = (specialist − x) / σ

# least-squares weight, clipped to [0, 1]
w = clip( −eg·(es−eg) / ‖es−eg‖², 0, 1 )

# final completion
x̂ = (1 − w)·general + w·specialist

This is a closed-form fit of one number per matrix. No neural network weights change, and no held-out values are used.

general 65%
specialist 35%

Both experts contribute. MatrixFormer+ reports the fitted weight in model.last_decision["specialist_weight"].

Quickstart

Needs Python 3.10+, PyTorch 2.4+, NumPy and huggingface-hub. Weights download automatically from Hugging Face on first use. A GPU is optional.

bash · CPU setup
git clone https://github.com/jacobf18/MatrixFormer.git
cd MatrixFormer
python3 -m venv .venv && source .venv/bin/activate
python -m pip install "torch>=2.4,<3" --index-url https://download.pytorch.org/whl/cpu
python -m pip install .
python -m matrixformer --device cpu --precision float32   # runs a small demo

For an NVIDIA GPU, install PyTorch from the PyTorch selector instead. See the README for Windows and troubleshooting.

python
import numpy as np
from matrixformer import MatrixFormerPlus

matrix = np.array([
    [1.0, 2.0, np.nan],
    [2.0, np.nan, 6.0],
    [3.0, 6.0, 9.0],
])

model = MatrixFormerPlus.from_pretrained(device="cpu", precision="float32")
completed = model.impute(matrix)

print(completed)
print(model.last_decision)   # blend weight and reconstruction errors

Use device="cuda" on a GPU, where the default amp_bfloat16 precision is used. Reuse the model object across matrices.

python -m matrixformer --input matrix.npy --output completed.npy \
    --device cpu --precision float32

Good to know

  • Mark missing values with np.nan. Zeros and sentinels like -999 are treated as observed.
  • Matrices larger than the context window are processed in overlapping windows; normalization uses the whole matrix.
  • Predictions are point estimates (means), not calibrated uncertainty intervals.
  • This package uses a generic column-normalized recipe. It does not include the benchmark-specific preprocessing behind some paper tables, so results there are not reproduced exactly. Benchmark results are in the paper.
